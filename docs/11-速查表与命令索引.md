# 11 · 速查表与命令索引

## 一、先建立直觉

### 1.1 三句话记住全部

1. **谁在访问**：进程的 `euid`（权限身份）+ `fsuid`（文件检查）+ `CapEff`（特权）；
2. **访问什么**：文件的 `mode/ACL`、目录的 `x` 位、端口的 capability、socket 文件的模式、挂载卷的属主；
3. **规则是什么**：属主 → 属组/ACL → other → capability → LSM/挂载选项。

### 1.2 排障决策树（一页纸）

```text
报错是什么？
├─ EACCES (13) Permission denied
│  ├─ 打不开文件？ → 看父目录 x 位 + 文件 mode/ACL + 进程 euid/组
│  ├─ 进不去目录？ → 看该目录 x 位（每一级都要）
│  ├─ 执行失败？   → 看文件 x 位、挂载 noexec、解释器权限、脚本 shebang
│  ├─ 写不进去？   → 看父目录 w+x、文件 w、sticky 位、只读挂载
│  └─ bind 端口失败？ → 看 uid + CAP_NET_BIND_SERVICE + ip_unprivileged_port_start
├─ EPERM (1) Operation not permitted
│  ├─ 有权限位但仍然失败 → 看 capability（CapEff）、LSM（dmesg/journalctl）、immutable(chattr)
│  ├─ 改所有权/改模式失败 → 需要属主或 CAP_CHOWN/CAP_FOWNER
│  └─ 容器内操作失败 → 看容器 cap 集/Bounding（capsh --print）
└─ 其它
   ├─ EROFS   → 只读挂载
   ├─ ENOENT  → 路径不存在（也可能是父目录不可搜索）
   └─ ENOTDIR → 路径中间是文件
```

## 二、按主题速查

### 2.1 身份与账户

| 目的 | 命令 | 备注 |
|---|---|---|
| 看当前身份与组 | `id` | `uid/gid` + 辅助组 |
| 看某用户 | `getent passwd <user>` | 走 NSS，比 `grep /etc/passwd` 可靠 |
| 看某组及成员 | `getent group <group>` | 成员在第 4 字段 |
| 看进程凭证 | `grep -E '^(Uid|Gid|Groups|Cap|NoNewPrivs)' /proc/<pid>/status` | 四套 uid |
| 看进程的 euid（可读） | `ps -o user,euser,ruid,euid,suid -p <pid>` | `ps` 的 `suid` 是 saved uid |
| 建用户（需 root） | `useradd -m -s /bin/bash -u 1500 alice` | 容器内验证 |
| 建系统用户 | `useradd --system --shell /usr/sbin/nologin --home-dir /var/lib/app app` | 服务账户 |
| 改用户 | `usermod -aG devs alice` | `-a` 必须带，否则覆盖组 |
| 锁账户 | `usermod -L alice` / `passwd -l alice` | shadow 里加 `!` |
| 看密码策略 | `chage -l alice` | 过期/最短/最长 |
| 切身份 | `su - alice` / `sudo -u alice -i` | `-` 加载登录环境 |
| 看当前用户能 sudo 什么 | `sudo -l` | 需要 sudo 权限 |

### 2.2 文件权限

| 目的 | 命令 | 备注 |
|---|---|---|
| 看权限 | `ls -l` / `ls -ln`（数字 uid） | `-n` 避免名字掩盖问题 |
| 看 12 位 mode | `stat -c '%a %A %U:%G %n' <f>` | `%a` 八进制，`%A` 符号 |
| 看路径每一级 | `namei -l /a/b/c` | 排查「父目录缺 x」神器 |
| 改权限 | `chmod 640 f` / `chmod u+x,g-w,o= f` | `X` 只给目录加 x |
| 递归（危险） | `chmod -R` / `chown -R` | 先 `--dry-run` 或用 `find -exec` |
| 改属主 | `chown alice:devs f` | 需 CAP_CHOWN |
| 默认 umask | `umask` / `umask -S` | 新文件 666 & ~umask，新目录 777 & ~umask |
| 临时 umask | `(umask 077; touch secret)` | 子 shell 内生效 |

### 2.3 特殊位、ACL、扩展属性

| 目的 | 命令 | 备注 |
|---|---|---|
| 设 setuid | `chmod 4755 prog` | 只对可执行文件有效；脚本无效 |
| 设 setgid 目录 | `chmod 2775 shared && chgrp devs shared` | 新文件继承组 |
| 设 sticky | `chmod 1777 /tmp/shared` | 只能删自己的文件 |
| 看特殊位 | `stat -c '%A' f` | `s/S/t/T` 大小写含义不同 |
| 看 ACL | `getfacl -p f` | `#effective` 是真正生效的权限 |
| 加 ACL | `setfacl -m u:alice:rw f` | 需要文件系统支持 ACL |
| 设默认 ACL | `setfacl -d -m u:alice:rwx dir` | 只对目录，影响新建文件 |
| 删 ACL | `setfacl -b f` / `setfacl -k dir` | `-b` 全删，`-k` 删 default |
| ACL 备份/恢复 | `getfacl -R . > acl.bak`；`setfacl --restore=acl.bak` | 迁移时用 |
| 看 xattr | `getfattr -d -m - f`（需 attr 包） | 文件 capability 也在这里 |
| 看不可变标志 | `lsattr f` | `i` 不可改/删，`a` 只能追加 |

### 2.4 提权与降权

| 目的 | 命令 | 备注 |
|---|---|---|
| 看文件 capability | `getcap -r / 2>/dev/null` | 需 libcap2-bin |
| 加文件 capability | `setcap cap_net_bind_service=ep /usr/sbin/nginx` | 需 CAP_SETFCAP |
| 去文件 capability | `setcap -r <file>` | — |
| 看进程 capability | `capsh --print` / `/proc/<pid>/status` | Current/Bounding |
| 以其他用户跑命令 | `setpriv --reuid=1000 --regid=1000 --clear-groups cmd` | 需相应权限 |
| 禁止 exec 提权 | `setpriv --no-new-privs cmd` | setuid/文件 cap 失效 |
| sudo 免密规则 | `/etc/sudoers.d/` + `visudo -c` | `alice ALL=(ALL) NOPASSWD: /bin/systemctl` |
| 降权顺序（写代码） | `setgroups → setgid → setuid → PR_SET_NO_NEW_PRIVS → capset(0)` | 顺序错了会残留权限 |
| systemd 服务身份 | `User=`, `Group=`, `NoNewPrivileges=yes`, `CapabilityBoundingSet=` | `systemctl cat <svc>` 查看 |

### 2.5 namespace 与 uid 映射

| 目的 | 命令 | 备注 |
|---|---|---|
| 进假 root | `unshare -Ur sh` | 只映射当前 uid→0 |
| 看映射 | `cat /proc/self/uid_map` | 格式：内部 uid 外部 uid 长度 |
| 看嵌套进程 | `ls -n /proc/<pid>/uid_map` | 65534 = 未映射 |
| 看 subuid 配置 | `cat /etc/subuid /etc/subgid` | rootless 容器依赖它 |
| 用 subuid 映射 | `newuidmap <pid> 0 <subuid> 65536` | 需要 newuidmap 与 subuid |
| 进容器 namespace | `nsenter -t <pid> -m -u -i -n -p sh` | 排障容器用 |
| 看命名空间 | `ls -l /proc/<pid>/ns/` | 对比 inode 判断是否同 ns |

### 2.6 Docker

| 目的 | 命令 | 备注 |
|---|---|---|
| 看 daemon 是否 rootful | `docker info --format '{{.SecurityOptions}}'` | 无 userns 即 rootful |
| 看容器内身份 | `docker run --rm alpine id` | 默认 root |
| 指定用户 | `docker run --rm -u 1000:1000 alpine id` | 可写数字 |
| 指定附加组 | `docker run --rm --group-add 989 alpine id` | 如 docker 组 |
| 写宿主目录失败 | `docker run --rm -u 101:101 -v "$PWD/data":/data alpine touch /data/x` | 看宿主目录属主 |
| 修宿主目录属主 | `sudo chown -R 101:101 data` 或容器内 `chown` | 注意安全 |
| 看容器 cap 集 | `docker run --rm --cap-add ALL debian:13 capsh --print`（先装包） | 对比默认 14 个 |
| 看卷属主 | `docker volume inspect <vol>`，容器内 `ls -ldn /data` | 命名卷首次从镜像继承 |
| 看 docker.sock 权限 | `stat -c '%a %U:%G' /var/run/docker.sock` | 660 root:docker |
| 谁在 docker 组 | `getent group docker` | 组成员 ≈ root |
| rootless 检查 | `docker info --format '{{.Rootless}}'` | 需 rootless 安装 |

### 2.7 Nginx

| 目的 | 命令 | 备注 |
|---|---|---|
| 看进程模型 | `ps -o pid,ppid,user,args -C nginx` | master=root，worker=nginx/www-data |
| 看 worker 用户 | `id nginx` / `id www-data` | 发行版/镜像不同 |
| 看配置里的 user | `grep -rn '^user' /etc/nginx/nginx.conf` | 仅 master 是 root 时生效 |
| 测状态码 | `curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/路径` | 403/404 排查 |
| 看错误日志 | `tail -n 50 /var/log/nginx/error.log` | 找 `13: Permission denied` |
| 测试配置 | `nginx -t` | 改完先测 |
| 看完整配置 | `nginx -T` | 含 include 展开 |
| 重载 | `nginx -s reload` / `systemctl reload nginx` | user 指令改动也需要 reload |
| 端口权限 | `ss -ltnp` + `getcap $(command -v nginx)` | <1024 看 cap/sysctl |
| 非特权端口阈值 | `cat /proc/sys/net/ipv4/ip_unprivileged_port_start` | 宿主常见 1024，容器内 0 |
| unix socket 权限 | `ls -l /run/php/php*-fpm.sock` | nginx worker 需 rw |

### 2.8 排障专用

| 目的 | 命令 | 备注 |
|---|---|---|
| 谁在阻止我 | `strace -f -e trace=openat,execve,connect <cmd>` | 看 errno=EACCES 的那次调用 |
| LSM 是否拒绝 | `dmesg \| tail -20`、`journalctl -k \| tail` | AppArmor/SELinux 拒绝日志 |
| 审计账户操作 | `ausearch -m USER_ACCT -i`、`lastb` | 需 auditd |
| 看谁登录过 | `last`、`lastlog`、`who` | — |
| 看失败登录 | `faillock`、`lastb` | 需 pam_faillock |
| 找 world-writable | `find / -xdev -type f -perm -0002 2>/dev/null` | 安全审计 |
| 找 setuid | `find / -xdev -perm -4000 -type f 2>/dev/null` | 安全审计 |
| 找无主文件 | `find / -xdev -nouser -o -nogroup 2>/dev/null` | 删用户后遗留 |

### 2.9 权限位与日志关键词速查

**12 位 mode 一眼读**（`stat -c '%a %A'`）：

| 八进制 | `ls -l` 显示 | 含义 |
|---|---|---|
| `4755` | `-rwsr-xr-x` | setuid + 属主可执行；其他人也可执行 |
| `4644` | `-rwSr--r--` | setuid 位在，但**属主没有 x**（配置错误） |
| `2775` | `drwxrwsr-x` | 目录 setgid：新文件继承属组 |
| `2644` | `-rw-r-Sr--` | setgid 位在，但组没有 x |
| `1777` | `drwxrwxrwt` | sticky：只能删自己的文件（`/tmp`） |
| `1666` | `-rw-rw-rwT` | sticky 位在，但 other 没有 x |
| `644` | `-rw-r--r--` | 普通文件默认（umask 022） |
| `755` | `-rwxr-xr-x` | 可执行文件/公开目录默认 |
| `600` | `-rw-------` | 私密文件（ssh key、.env） |

> `s/S`、`t/T` 的区别只有一条：**大小写表示对应的 x 位是否也存在**。大写 = 特殊位在但 x 位缺失。

**日志/报错关键词 → 去哪查**：

| 关键词 | 含义 | 下一步 |
|---|---|---|
| `Permission denied` / `EACCES(13)` | mode/ACL/目录 x 拒绝 | `namei -l` + `getfacl` + `id` |
| `Operation not permitted` / `EPERM(1)` | capability/LSM/immutable | `CapEff`、`dmesg`、`lsattr` |
| `Read-only file system` | 只读挂载 | `findmnt -T` |
| `open() ... failed (13: Permission denied)`（nginx） | worker 读不到文件/目录 | `ps -o user -C nginx` + `namei -l` |
| `mkdir() ... failed (13: Permission denied)`（nginx） | master 建缓存/日志目录失败 | 缓存路径属主、挂载覆盖 |
| `connect() ... failed (13: Permission denied)`（nginx） | unix socket 写权限不足 | `ls -l <sock>` |
| `bind() ... failed (13: Permission denied)` | 端口 <1024 且无 `CAP_NET_BIND_SERVICE` | `ip_unprivileged_port_start`、cap |
| `authentication failure`（sudo） | 密码/策略/时间戳 | `sudo -l`、`/etc/sudoers.d/` |
| `dubious ownership`（git） | 仓库属主与当前用户不一致 | `chown -R` 或 `safe.directory` |
| `cannot open directory ... Permission denied` | 目录缺 x | `chmod +x` 或 ACL |

**关键文件位置**：

| 文件 | 作用 | 典型权限 |
|---|---|---|
| `/etc/passwd` | 账户（所有人都可读） | `644 root:root` |
| `/etc/shadow` | 密码哈希/锁定状态 | `640 root:shadow` |
| `/etc/group` | 组与成员 | `644 root:root` |
| `/etc/gshadow` | 组密码/管理员 | `640 root:shadow` |
| `/etc/login.defs` | UID 范围、umask、密码策略 | `644 root:root` |
| `/etc/nsswitch.conf` | 账户解析顺序 | `644 root:root` |
| `/etc/subuid`、`/etc/subgid` | rootless/userns 的 subordinate ID | `644 root:root` |
| `/etc/sudoers`、`/etc/sudoers.d/*` | sudo 策略 | `440 root:root` |
| `~/.ssh/`、`authorized_keys` | SSH 密钥 | `700`、`600` |
| `/var/run/docker.sock` | Docker API | `660 root:docker` |
| `/etc/nginx/nginx.conf` | nginx 主配置（`user` 指令） | `644 root:root` |
| `/var/log/nginx/error.log` | 403/权限错误证据 | 发行版不同 |
| `/run/php/php*-fpm.sock` | php-fpm unix socket | `660 www-data:www-data` 常见 |

## 三、动手验证

### 3.1 把速查表用在一道真实题上

场景：`nginx` 返回 403，日志里是 `open() "/srv/www/index.html" failed (13: Permission denied)`。

```bash
# 1) 谁在访问？看 worker 进程的 uid
ps -o pid,user,args -C nginx
#    nginx 12345 nginx  nginx: worker process   ← uid 101

# 2) 访问什么？看路径每一级
namei -l /srv/www/index.html
#    drwxr-xr-x root root /srv
#    drwxr-x--- root root /srv/www      ← 缺 other 的 x！
#    -rw-r----- root root index.html

# 3) 规则？worker 是 uid 101，/srv/www 是 750 root:root → 进不去
# 4) 修：chmod o+x /srv/www（或把 www 组改为 nginx 并 chmod 750）
```

> 完整案例与更多场景见 [09-权限排障手册](09-权限排障手册.md)。

### 3.2 一条命令自查「我为什么不行」

```bash
# 以目标用户身份模拟检查（需要 root/sudo）
sudo -u nginx test -r /srv/www/index.html && echo readable || echo NOT-readable
sudo -u nginx namei -l /srv/www/index.html

# 没有 sudo 时：对比 uid/组与文件的 mode
id nginx; ls -ln /srv/www/index.html; getfacl -p /srv/www/index.html
```

## 四、常见误解

❌ **「chmod 777 能解决所有权限问题」**
✅ 它只改 mode，解决不了 capability、LSM、只读挂载、父目录缺 x、uid 映射、端口策略；而且会让问题更不安全。

❌ **「目录有 r 就能进」**
✅ 进入目录需要 `x`，列目录需要 `r`；只有 `r` 没有 `x` 时 `ls` 得到的是名字但进不去/读不了。

❌ **「文件属主决定能不能删」**
✅ 删除/改名看**父目录的 w+x**（和 sticky 位）；文件自身的 w 位不影响删除。

❌ **「`sudo` 失败就是密码错」**
✅ 可能是 sudoers 规则、`no_new_privs`、`/etc/sudo.conf` 属主、`requiretty`、用户不在 sudo 组。

❌ **「容器里的 root 就是宿主 root」**
✅ 取决于 userns-remap/rootless；本机默认 rootful 时 uid 相同，但 cap 被削减且挂载范围有限。

❌ **「把用户加进 docker 组只是方便」**
✅ 等价于给 root：可以通过 `docker run -v /:/host` 读写宿主任意文件（07 章详解）。

❌ **「文件显示属主 nobody 就是 nobody 用户」**
✅ 65534 通常表示 uid 在当前 namespace 未映射（溢出 UID）。
