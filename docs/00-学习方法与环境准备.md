## 一、先建立直觉

### 1.1 这套课想解决什么

Linux 权限相关的知识通常散在三类资料里：

- **命令手册**：告诉你 `chmod 755` 怎么用，但不解释目录的 `x` 位为什么是「通行证」；
- **内核文档**：讲清了 `cred` 和 capability，但不告诉你 nginx 为什么 403；
- **应用文档**：教你怎么配 nginx/docker，但不说清「容器里的 root」到底是谁。

结果是：**知识是碎片，遇到问题时只能试。** 这套课把它们连成一条线：

```text
一个现象（403 / Permission denied / 容器里写不进挂载目录）
  → 谁在访问（进程凭证：uid/gid/cap）
  → 访问什么（文件 mode/ACL、端口、socket、卷）
  → 规则是什么（检查顺序、namespace 映射、LSM）
  → 怎么验证（命令）
  → 怎么修（最小改动）
```

### 1.2 三条学习路线

| 路线 | 适用 | 顺序 | 时间 |
|---|---|---|---|
| **速成（1 天）** | 明天就要排查线上权限问题 | 01 → 03 → 04（只读第二节）→ 07 → 08 → 09 | 4~6 小时 |
| **系统（1 周）** | 想把模型真正建起来 | 00 → 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10 → 11 | 每天 1.5~2 小时 |
| **实战（按需）** | 只解决手头问题 | 直接看 09 的案例，再回溯对应章节 | 30 分钟/问题 |

> 不管理哪条路线，**01 章必须先读**——它是全书的地图，后面的章节都在往这张图上挂细节。

### 1.3 你需要两套实验环境

本机（以及大多数人的开发机）有一个现实：**你通常不是 root，也不该拿生产机器做实验**。
所以本课程把实验分成两类，各自有明确边界：

```text
┌─────────────────────────────┐      ┌──────────────────────────────────┐
│ A. 宿主：只读观察 + 自有文件  │      │ B. 容器：真正的 root 实验环境      │
│  id / proc / stat / getfacl │      │  useradd / chown / setuid / caps  │
│  unshare -Ur（假 root）      │      │  docker run --rm debian:13 ...    │
│  不需要任何特权               │      │  容器 root 是宿主 root（默认）     │
└─────────────────────────────┘      └──────────────────────────────────┘
```

- **A 类**用于「观察」：看自己的凭证、看文件元数据、看挂载选项、看 namespace 映射；
- **B 类**用于「制造现象」：建用户/组、设置 setuid、给文件加 capability、复现 403、复现卷属主问题。

> 重要：容器 root **默认就是宿主 root**（未启用 userns-remap 时），所以容器实验只挂载工作区目录，
> 不要执行 `-v /:/host` 这类操作。07 章会解释为什么这既是教学工具，也是安全风险。

### 1.4 本机的真实环境（先看清楚，避免照抄网上命令）

本课程在一台 **Debian 13 / 内核 6.12** 的机器上编写，但会话运行在一个受限沙箱里：

```text
$ id
uid=1000(demo) gid=1000(demo) 组=1000(demo),65534(nogroup)

$ grep -E '^(CapEff|NoNewPrivs)' /proc/self/status
CapEff:	0000000000000000
NoNewPrivs:	1

$ findmnt -T /home/demo -o TARGET,FSTYPE,OPTIONS
TARGET       FSTYPE OPTIONS
/home/demo ext4   rw,nosuid,nodev,relatime,errors=remount-ro
```

这意味着：

| 你想做的事 | 宿主上的结果 | 本课程的做法 |
|---|---|---|
| `sudo ...` | `sudo: 已设置"no new privileges"标志...` | 用容器内 root |
| `useradd` / `usermod` / `groupadd` | 命令不存在 | 容器 `debian:13` 内执行 |
| `getcap` / `setcap` / `capsh` | 未安装 | 容器内 `apt-get install libcap2-bin` |
| 给文件设 setuid 后提权 | `/home` 挂载 `nosuid` + 无 root 属主文件 | 容器 overlay 文件系统内做 |
| 读 `/etc/shadow` | 权限不足（且本会话里显示为 65534 属主） | 只观察格式，不在宿主读 |
| `chattr +i` | `chattr: 不允许的操作` | 容器 + `--cap-add LINUX_IMMUTABLE`（或只读讲解） |

**这不是教程的缺陷，而是真实世界的一部分**：受限环境、容器、userns 正是这套课要讲的内容。
06/07 章会解释为什么你的文件会显示成 `nobody`（溢出 UID）、为什么容器里的 root 看起来能在宿主地盘写文件。

## 二、环境准备

### 2.1 三种可用环境（任选）

**环境 1：任意 Linux 机器（推荐，最接近生产）**

如果你有一台可以 `sudo` 的测试机（虚拟机/云主机都行），90% 的实验可以直接在宿主机跑。
注意：不要在**生产机器**上执行课程里的 `chmod -R`、`useradd`、`setcap` 等命令，先建快照。

**环境 2：本机 + Docker（本课程默认）**

- 需要 Docker（本项目实测 29.8.1，rootful）；
- 本机镜像清单里最好有 `debian:13`、`alpine`、`nginx:1.20-alpine`；
- 所有「需要 root」的实验都通过 `docker run --rm ... debian:13` 完成。

**环境 3：容器内的完整 root（也可用 podman）**

如果本机没有 Docker，但可以用 `podman` 或 CI 容器，原理一致；把下面命令里的 `docker run`
换成 `podman run` 即可（注意 podman 默认 rootless，uid 映射行为不同，见 06 章）。

### 2.2 一条命令自检

```bash
cd learn-ugroup   # 进入仓库根目录
bash scripts/env-check.sh
```

它会检查：当前用户与 capability、`/home` 挂载选项、`unshare -Ur` 是否可用、
`getfacl`/`gcc`/`curl`/`docker` 是否可用、镜像是否就绪、`ip_unprivileged_port_start`、
`/etc/subuid`、可用端口，并打印一张「本机能跑哪些实验」的能力矩阵。

> 自检不改变系统状态，全部只读；某项 `SKIP` 只表示该实验需要换个环境，不影响其他实验。

### 2.3 工具清单（按需安装）

| 工具 | 提供什么 | Debian/Ubuntu | RHEL 系 |
|---|---|---|---|
| `acl` | `getfacl`/`setfacl` | `apt install acl` | `dnf install acl` |
| `attr` | `getfattr`/`setfattr`/`lsattr` | `apt install attr` | `dnf install attr` |
| `libcap2-bin` | `getcap`/`setcap`/`capsh` | `apt install libcap2-bin` | `dnf install libcap` |
| `sudo` | `sudo`/`visudo` | `apt install sudo` | 通常预装 |
| `strace` | 跟踪 open/execve 的系统调用 | `apt install strace` | `dnf install strace` |
| `docker.io`/`docker-ce` | 容器实验环境 | 见官方文档 | 见官方文档 |
| `nginx` | 真实 nginx 服务（可选） | `apt install nginx` | `dnf install nginx` |
| `gcc` | 编译 setuid/capability 演示程序 | `apt install gcc libc6-dev` | `dnf install gcc` |

> 本课程不要求全部安装：`scripts/env-check.sh` 会告诉你缺什么，缺的部分用容器补。

### 2.4 实验目录约定

```text
labs/
├── 01-permission-model/     # 宿主：凭证、umask、特殊位、目录 x、fd
├── 02-acl/                  # 宿主：ACL 机制（含可选容器跨 uid 验证）
├── 03-userns-subuid/        # 宿主：user namespace 与 uid 映射
├── 04-setuid-caps/          # 容器：setuid、no_new_privs、文件 capability
├── 05-docker-uid/           # 容器：容器 root、-u、卷属主
├── 06-nginx-perm/           # 容器：nginx master/worker 与 403
└── 07-drills/               # 混合：5 个故障场景的排障演练
```

每个实验目录都有 `README.md`（含真实运行输出）和 `run.sh`。运行方式统一：

```bash
cd labs/01-permission-model
bash run.sh
```

约定：

- `run.sh` 不交互、可重复运行、最后打印 `PASS n / FAIL m`；
- 依赖缺失时打印 `SKIP` 并退出 0（不会让整门课卡住）；
- 临时文件放在实验目录下的 `.tmp/`，退出时清理；
- 需要容器的实验用 `--rm` + 唯一容器名，脚本退出时清理。

### 2.5 安全边界（务必遵守）

1. **只在实验目录里折腾**；不要对 `/`、`/etc`、`/home` 执行 `chmod -R`/`chown -R`。
2. 课程里的 `docker run -v` 只挂载实验目录；看到 `-v /:/host`、`--privileged` 的命令，**只读不跑**。
3. `docker` 组 ≈ root（07 章详解）。生产机上不要随便把用户加进 `docker` 组。
4. 不要在共享机器上创建/删除真实用户，除非你明确知道影响。
5. 每章「动手验证」给出的命令都标注了「宿主 / 容器 / 需要 root」，照标注执行。

## 三、动手验证

### 3.1 五分钟上手

```bash
cd learn-ugroup   # 进入仓库根目录

# 1) 环境自检（只读）

# 2) 宿主可跑：观察自己的凭证、umask、特殊位、目录 x、fd 语义

# 3) 宿主可跑：ACL 机制
cd labs/02-acl && bash run.sh && cd ../..

# 4) 宿主可跑：进入假 root，观察 uid 映射
cd labs/03-userns-subuid && bash run.sh && cd ../..

# 5) 容器（需要 docker）：setuid / capability
cd labs/04-setuid-caps && bash run.sh && cd ../..

# 6) 容器（需要 docker）：nginx 403 复现
cd labs/06-nginx-perm && bash run.sh && cd ../..
```

> 先跑实验再读文档也可以：每个实验 README 的第一节就是「你会看到什么现象」。

### 3.2 每章的标准读法

1. **先读「一、先建立直觉」**：不要求记住细节，只要知道这章在解决什么问题；
2. **再读「二」**：遇到表格就停下来，用自己的机器敲一遍对应的观察命令；
3. **跑「三、动手验证」**：实验输出和正文对不上时，先怀疑环境差异（发行版/版本/挂载选项）；
4. **做「四、常见误解」**：每条都问自己「我是不是也这么以为」；
5. **收藏「五、速查表」**：排障时直接回来查。

### 3.3 验证记录怎么记

建议在自己的笔记里对每个结论记三行：

```text
结论：nginx worker 以 uid 101 运行
验证：容器内 ps -o user,args；看到 "nginx nginx: worker process"
边界：容器镜像 nginx:1.20-alpine；官方镜像的 user 是 nginx，Debian 包安装默认是 www-data
```

第三条「边界」最重要：**同一个知识点在不同发行版/镜像里名字可能不同，但模型不变。**

## 四、常见误解

❌ **「我不是 root，所以这些实验做不了」**
✅ 宿主上能做大量只读观察（凭证、stat、getfacl、unshare、挂载选项），需要 root 的部分用容器补。
（验证：`unshare -Ur id` 在宿主即可得到 uid=0）

❌ **「容器里的 root 和宿主 root 完全一样」**
✅ 默认 rootful 下 uid 相同，但 capability 被削减、有 seccomp/AppArmor，且挂载了哪些目录才是关键。
（验证：容器内 `capsh --print` 只有 14 个 cap）

❌ **「照着网上命令抄就行」**
✅ 发行版差异很大：`adduser` vs `useradd`、`www-data` vs `nginx`、`sites-enabled` vs `conf.d`。
本课程会标注「本机 / 容器 / 发行版」边界。

❌ **「先学应用（nginx/docker），原理以后再说」**
✅ 应用章的每个故障都能回溯到 01 章的三要素；跳过模型会导致「修好了但不知道为什么」。
（建议至少先读 01 章第一节）

❌ **「实验跑不过就是教程错了」**
✅ 先看实验 README 的「前置条件」和「已知限制」；本机沙箱缺 root、缺包、`/home` 挂 nosuid 都会影响结果，
实验脚本对这些情况会打印 `SKIP` 而不是失败。

❌ **「把 /home 挂载成 nosuid 是坏事」**
✅ 这是常见的安全加固（防止用户放置 setuid 程序提权）；代价是「你在这里测试 setuid 会失效」。
（验证：`findmnt -T /home/demo` 的 OPTIONS 列）
